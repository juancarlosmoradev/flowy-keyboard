# Contributing

## Workflow

1. Pick one user-visible feature.
2. Write its expected behavior and acceptance criteria.
3. Implement the smallest complete change.
4. Run the relevant automated checks and record manual device checks.
5. Update product or architecture documentation only when the behavior or a decision changes.

## Pull requests

Include the user problem, behavior change, verification performed, and known limitations. Keep code free of comments unless a comment explains a non-obvious constraint.
